popcorn Platform Topology — Staging & Production

Both EKS environments run in parallel from the same GitHub repos. Staging (us-west-1) and the new production EKS build (us-east-1) are fully separate clusters with separate data — except production EKS, which deliberately shares RDS/S3/Qdrant with the still-live EC2 production while it proves itself out on test.popcorn.io. No DNS cutover has happened yet.

Reading this diagram
  • Solid arrows are runtime traffic/data paths. Dashed arrows are GitOps management (Argo CD syncing a Deployment) or monitoring scrape paths — not request traffic.
  • Production EKS and the live EC2 app connect to the same RDS, S3 buckets, and Qdrant instance over a VPC peering connection — this is a deliberate choice so test.popcorn.io validates against real data, not a copy.
  • Cutover (moving api.popcorn.io from EC2 onto this EKS platform) is a future, separate, explicitly-confirmed DNS change — not implied by anything in this diagram.
  • Full written reference: popcorn-gitops/docs/PRODUCTION_ARCHITECTURE.md and popcorn-gitops/docs/PLATFORM_ARCHITECTURE.md (staging).
